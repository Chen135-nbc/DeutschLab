# Codex 工作任务｜DeutschLab A1 自学拓展框架与能力树骨架

## 背景与目标
当前 DeutschLab 应用外壳已完成。请先检查现有仓库、技术栈、路由、组件与持久化方案，不要假设项目是 React、SwiftUI 或其他技术栈，也不要无必要重构已有页面。

本阶段只实现 **A1 自学拓展框架 + A1 能力树的结构化骨架**。教材 Studio21 的单元映射、详细讲义、题库、智能副本及实际能力评估以后再逐步填充。

请将同目录下的以下文件作为唯一初始内容来源：
- `a1_extension_framework.json`：原始 A1 自学框架的 8 大板块、68 单元、207 条细分内容，以及板块说明、A2 衔接和完成标准。
- `a1_ability_tree.json`：引用这些相同 ID 的能力树配置（8个分支、68个主题节点），初期不增加杜撰的能力叶片。

用户上传的 PDF 是《德语 A1 自学专题框架 · 新版》。本阶段必须维持其原有标题、层级、单元顺序和细分学习内容。不得擅自改动为常规 A1 教材目录或把当前教材进度误写为已掌握。两个 JSON 不包含具体 Studio21 单元对应关系，这是刻意预留。

## 需要开发的功能
1. **A1 拓展目录**：一级板块 → 单元 → 细分内容；板块详情可查看本板块定位、A1→A2 衔接、完成标准；允许搜索标题及内容。首版只读即可。
2. **A1 能力树**：使用相同的板块和单元层级展示树干/枝干/主题节点；点击节点进入对应自学专题详情。视觉先简洁、可操作，不开发复杂树木动画。
3. **状态区别**：学习覆盖状态（未开始 / 部分覆盖 / 已学习）和运用能力状态（未评估 / 练习中 / 自评掌握 / 有评估证据）分开记录和展示。初始默认都是未开始、未评估，不得因为导入目录就自动点亮全部节点。
4. **部分覆盖能力**：为207个细分内容保留稳定 ID，今后一个 Studio21 单元可以只关联其中一部分；一个自学专题可以关联多个主线单元。映射关系先留空，界面可显示“尚未关联主线”。
5. **增量结构**：未来可增加 A2/B1/B2 等级、新增学习内容、附加副本、词汇/语法知识节点，而不修改既有主题 ID。用户学习记录、能力评估与静态课程目录数据必须分离。
6. **非破坏性导入**：首次导入与再次执行相同导入不能生成重复板块/单元；更新目录不得删除已有用户进度。若迁移方案不明确，请先提出并等待确认，不进行破坏性数据库变更。
7. **状态真实性**：课程学过 ≠ 能独立运用；选择题正确 ≠ 口语掌握；未来副本剧情点击 ≠ 口语评分。能力状态必须有独立证据或明确的自评来源。

## 暂时不做
- 不制作 Studio21 全部课程内容与对应关系；不猜测教材中尚未提供的章节。
- 不制作详细教学讲义、词汇列表、练习题或剧情副本。
- 不接入 GPT API，也不做自动口语评分、云端同步或复杂图谱。
- 不根据 PDF 里的旧式“每日学习闭环”强制恢复每个单元的完整六步练习；本项目已决定主线精简，基础造句位于拓展学习，综合训练交给副本。

## 建议工作顺序
A. 先检查仓库，并简述计划修改的文件、页面、数据导入方式和进度模型。
B. 实现A1目录可浏览/搜索和能力树可导航的最小版本。
C. 以非破坏性方式导入两份 JSON 中的结构，不预先生成全部用户学习记录也可以，由访问时使用默认状态呈现。
D. 添加最小自动化测试，至少覆盖：8板块、68单元、207内容项、16完成目标；稳定 ID 唯一；重复导入无重复；节点跳转正常；进度数据不被覆盖；未评估不显示为掌握。
E. 运行现有测试或构建；报告运行方式、修改文件和剩余事项。

## 验收标准
- A1拓展目录显示完整且与源文件顺序、标题一致；可进入查看细分学习内容。
- A1能力树显示8个大分支和68个主题节点，点击可跳转到同一专题数据。
- 没有重复录入两套专题内容；不会把自学框架错当作 Studio21 主线。
- 状态可区分“学习”与“运用”，尚未训练时不得虚构成绩。
- 暂无具体练习或副本时显示“待填充/尚未开放”，不能出现虚假完成记录。
- 结构支持日后增量填充和课程映射，且不会意外覆盖历史进度。

请先检查现有工程结构并实施该范围。遇到需要破坏性迁移或修改已确认产品原则的选择，先说明方案、风险和影响，再请求确认。
