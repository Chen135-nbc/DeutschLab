## A. 请先理解产品基线

若仓库中存在《DeutschLab 产品设计初版报告 v0.2（2026-10-10）》、2026-10-10 阶段性报告、课程目录或自学框架，请先阅读；对新文档与旧文档有冲突的地方，先列出差异，优先以我最新确认的产品设计为准。若材料不存在，不要假装已阅读，不要猜测 Studio21 的真实章节与内容。你可以创建少量、清楚标注为 DEMO 的演示数据。

**产品定位**：DeutschLab 是仅供个人长期使用、以电脑本地运行优先的智慧德语学习工作台。它跟随 Studio21 真实教材/录播课程从 A1 逐步学到 B2；自学框架组织专题拓展、交际能力和副本主题；学习内容和软件功能都随实际学习进度逐渐生长。

**核心边界**：首版不依赖 GPT API、不部署云服务器、不开发手机端、不复刻完整背词 APP、不预建全部 A1–B2 内容或庞大的开放世界。ChatGPT 暂作场外语言教练与内容创作辅助，由我在手机应用上手动使用，软件不声称能自动同步 GPT 聊天或听懂电脑端语音。原生/桌面 Web 形式与本地数据库选型需要依据现有设备和环境再评估；不要先入为主地将 iCloud 自动同步当作已实现需求。

## B. 产品模块与规则（必须保留）

1. **Studio21 主线**：跟随真实教材顺序，包含单元概览、核心词汇四选一识读、基础语法匹配/选择/填空、简短检测和学习进度；主线不重复搭建整套口语、听力、写作课程。现有背词工具仅需保留跳转/关联能力。
2. **自学专题拓展**：基于既有 A1/A2 自学框架的板块与单元，按当前 Studio21 所学内容建立映射；包含拓展词汇、语法和场景讲解，以及以词形、变位、语序、冠词和格正确性为目标的**基础造句**。造句不同于表达丰富化练习。
3. **趣味副本**：综合情境练习以自学框架为主题骨架而非机械按 Studio21 章节排序；副本在对应拓展课内嵌，同时在主页有独立资源库入口。两个入口调用同一个副本 ID、内容版本和历史记录。课内入口默认为定向训练；独立入口允许定向训练与自由探索。副本可搜索、重玩、增补难度，不需要每次重新开发。
4. **平行德国人生**：作为副本类型之一，早期从面包房、教室、公共交通等有限生活场景出发，训练任务优先；随着课程推进，地点、人物、事件可以逐渐形成联系，不预设完整社会模拟。区分地点、NPC、剧情事件、语言训练任务；角色可以独立于玩家存在，合理允许一次性相遇。
5. **一句话的100种可能**：保存一个交际意图在不同等级、语境、语气与语体中的有价值的表达版本；这是表达深化功能，不能与基础语法造句合并。
6. **真实世界德语采集**：首版可手动保存真实文本及其主题、推荐等级和出处；后续扩展听力、阅读、写作任务，注意资料授权与出处。
7. **知识星系**：以词汇、语法、表达等知识节点与相互关系为基础，可跨能力树分支关联。首版只需列表及跳转，不做复杂宇宙动画。
8. **能力树**：以既有 A1、A2 自学专题框架的板块、单元及实际交际任务为主干；B1/B2 待学到后再扩展。课程“已接触/已学习”与“能独立运用/经复测”必须分开。自学框架节点可被多个 Studio21 单元部分覆盖，不可简单一对一。
9. **统一学习档案**：题目、知识点、副本等有稳定 ID；内容与用户记录分离；每次练习新增历史记录，不能覆盖旧成绩；客观题判分、自评、GPT建议不能混为同一证据。

## C. 副本交互的四个不同维度

- **入口**：拓展课内 / 主页副本库。
- **玩法**：定向训练 / 自由探索。
- **备注模式**：显示教学目标、提示和标签 / 隐藏备注以便沉浸。
- **剧情状态**：正式探索可在确认后更新世界事实与玩家已知信息；练习重玩原则上只记录学习表现，不改写正式剧情。

这四者是不同的概念，但界面应尽量简洁。玩家可先真实用德语开口，再点击剧情意图控制预设分支；**意图按钮只推动剧情，不代表口语评分**。未接入语音识别时，软件不能声称听懂了自由回答。只需有限、可汇合的分支，不做无限动态 NPC。

## D. 场外 ChatGPT 教练协作

每个适合开放口语训练的场景/事件可保存一份教练任务卡 Prompt：等级、目标、人物背景、NPC已知台词、待评知识点、反馈格式。电脑端显示“复制任务卡”，我手动发送至手机 ChatGPT。GPT仅做场外语法/自然度/得体性点评，不代替软件决定剧情。无法获取真实音频时，不得假装评价发音。首版允许将简短点评摘要/自评手动输入DeutschLab；不实现无API的自动回传。所有人工与外部反馈标注来源及可信度。

## E. 架构与数据预期

请先提出**概念数据模型**，至少包括：CourseUnit、FrameworkTopic、KnowledgeNode、PracticeItem、Quest、Scene、NPC、StoryEvent、WorldFact、PlayerKnownFact、PracticeAttempt、CourseProgress、SkillNode、ExternalCoachNote、ContentVersion/Revision；说明关键 ID 与多对多关系。不要在未经确认前过度细化几十张数据库表。

数据分为：
- 内容数据：课程/专题/知识点/题目/副本/角色/事件；允许增量导入和版本更新。
- 用户数据：学习进度、练习历史、自评、世界正式状态、玩家已知状态；持久化且支持备份与导出。

优先做到离线可运行；记录与内容更新应具备可追溯性。可考虑本地数据库与 JSON/Markdown 内容导入，但具体技术要先说明取舍。未来 iCloud 同步属延后事项，不作为 v0.1 完成条件；具体可行性取决于操作系统与应用架构。
